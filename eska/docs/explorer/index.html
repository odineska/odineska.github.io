Работа в ESKA Explorer

ESKA Explorer находится в активной разработке. Это руководство для VS Code и VSCodium. Откройте проект с исходниками Designer XML, внесите изменения и проверьте их в тестовой базе. Примеры для терминала используют общий CLI ESKA.

Руководство ESKA Справочник CLI

Открыть или создать проект

Откройте папку с eska.toml в VS Code или VSCodium. В проводнике раскройте ESKA: 1C Explorer и выберите Выбрать проект и подключиться. Если в рабочей области несколько папок, укажите корень нужного проекта. Для запуска локальных инструментов редактор запросит доверие к папке.

Если проекта ещё нет, откройте палитру команд и выберите Начать проект 1С. Дальнейшие шаги зависят от того, что у вас уже есть.

Исходные материалы Что выбрать в мастере Пример в терминале
Каталог с готовой выгрузкой Подключить исходники Designer XML. Укажите каталог проекта и папку с XML внутри него. eska init ./Учёт --source src
Файл конфигурации, расширения, обработки или отчёта Создать из CF / CFE / EPF / ERF. Укажите файл, родительскую папку и имя нового каталога. Для распаковки нужна установленная платформа 1С. eska new ./Аудит --from ./Аудит.epf
Репозиторий Клонировать Git-проект. Укажите URL либо путь к локальному репозиторию, затем новый каталог. eska clone ./Учёт ./Учёт-копия
Новый проект Создать новый проект. Выберите тип, каталог, платформу и процесс работы с Git. Мастер создаст каркас с манифестом. eska new ./Учёт --type configuration

Проверьте параметры перед подтверждением. Пункт Выбрать позже оставляет версию платформы в проекте незаданной. При распаковке файла платформа потребуется уже на этом шаге. Для новой конфигурации в пустом каталоге исходников начальный XML можно создать командой eska metadata create --kind configuration --name Учёт --no-input.

Подготовить компоненты и выбрать приложение

В палитре выберите Управление компонентами. Для дерева нужен eska-project, для форматирования — eska-fmt, для подсказок и диагностики BSL — bsl-analyzer-app. Действие Подготовить project, форматтер и языковой компонент помогает установить этот набор на машине, где работает расширение. В удалённой рабочей области это может быть другая машина.

Откройте Настроить проект. Общие параметры проекта хранятся в eska.toml, пути и профили этой машины — в .eska/settings_local.toml. В рабочей области с несколькими приложениями вызовите Выбрать приложение для анализа и укажите нужную конфигурацию с её расширениями. Выбор определяет, какие модули увидит анализатор и какие таблицы появятся в конструкторе запросов. Настройки проекта и приложений.

Если после обновления компонент перестал запускаться, в палитре найдите действие Восстановить установку для соответствующего инструмента. Собственный путь к исполняемому файлу проверяйте в настройках расширения. Версии совместимых выпусков и ссылки на загрузки приведены на странице установки.

Найти объект, модуль или предопределённый элемент

  1. Раскройте конфигурацию, затем Документы и нужный документ. Нажмите имя документа, чтобы посмотреть свойства. Раскройте Модули и выберите модуль объекта, чтобы открыть BSL. В контекстном меню Открыть XML показывает описание объекта, Открыть в новой вкладке оставляет предыдущую вкладку на месте.
  2. Если известно только имя или синоним, вызовите Поиск метаданных в заголовке дерева. Введите часть имени, например «заём». Выберите результат по типу, проекту и владельцу. Поиск охватывает ещё не раскрытые ветки. Пока строится индекс, список может пополняться. Если найдено больше 50 элементов проекта, уточните строку поиска.
  3. Для обратного перехода откройте файл исходника и выберите Показать открытый файл в дереве eska. У подписки на событие нажатие на имя ведёт к обработчику в общем модуле. У справочника ветка Предопределённые данные позволяет найти элемент и перейти в его XML.

В контекстном меню проекта доступны алфавитная сортировка и фильтр пустых групп. В рабочей области с несколькими подпроектами Отключить проект останавливает загрузку его дерева и фоновый поиск. Если его исходники нужны активному приложению, анализатор продолжит их использовать. Чтобы вернуть скрытый подпроект, выберите Показать отключенные, затем Включить проект.

В справочнике откройте группу Стандартные реквизиты, выберите «Пометка удаления» и посмотрите тип в свойствах. Открыть скринкаст.

В терминале команда eska metadata list --kind document --search Заём --format json ищет документы у выбранного владельца. Глобальный поиск по дереву, переход к открытому файлу, сортировка и фильтры относятся к интерфейсу редактора. Скринкаст о дереве.

Изменить свойство и проверить переименование

Откройте Свойства объекта. Строка поиска находит подписи, имена XML и значения. Ссылка на другой объект открывает его свойства, а Открыть XML у поля выделяет соответствующий элемент. У общей картинки здесь же можно посмотреть изображение и его размеры.

  1. Нажмите замок в панели свойств. У существующего синонима выберите строку нужного языка, введите текст и нажмите Enter. Esc отменяет ввод. Списки и флажки сохраняют выбор сразу.
  2. При изменении типа укажите допустимые параметры, например длину строки или разрядность и точность числа. Для ссылочного свойства выберите цель из предложенных объектов. Если поле доступно только для чтения, посмотрите причину в панели. Ограничения могут исходить из схемы объекта или из правил поддержки 1С.
  3. При смене Имени прочитайте обзор переименования. Проверьте пути, однозначные ссылки и случаи, требующие ручного решения. Для отмены применённой правки используйте историю панели. Если XML успел измениться на диске, перечитайте свойства и проверьте значение заново.

В терминале eska metadata inspect --object 'catalog:Товары' показывает свойства справочника. Для изменения одного поля подготовьте JSON по схеме, проверьте его через eska metadata check change.json, затем примените через eska metadata apply change.json. Для имени предусмотрены отдельные rename-preview и rename-apply. Справочник CLI · Скринкаст о свойствах.

Создать документ, реквизит и модуль

В группе Документы откройте контекстное меню, выберите Добавить… и задайте имя, например Заказ. Заполните предложенные обязательные свойства. В дереве нового документа раскройте Реквизиты и тем же действием добавьте строковый реквизит Комментарий. Для строки можно выбрать длину. Аналогично в группе Табличные части создайте Строки, затем добавьте реквизит уже у этой табличной части.

В меню документа или группы Модули выберите Добавить… и нужную роль. В списке показаны доступные отсутствующие модули. Созданный BSL-файл откроется в редакторе. Для этого действия нужен Metadata API 1.50. Откройте группу Формы, создайте форму Основная и перейдите к её структуре.

Для автоматизации ту же последовательность можно выполнить в корне проекта с исходниками конфигурации. Следующему вызову передавайте идентификатор владельца, который вернул предыдущий.

eska metadata create --kind document --name Заказ --no-input
eska metadata add attribute --owner 'document:Заказ' --name Комментарий --type string --length 100 --no-input
eska metadata create --kind form --parent 'document:Заказ' --name Основная --no-input
eska metadata object-schema --parent 'document:Заказ' --format json

Последняя команда покажет разрешённые роли для eska metadata create-module. Для нового объекта по образцу используйте Копировать объект метаданных…, задайте имя, проверьте список файлов. Копия получает свои UUID, вложенные объекты, формы и модули. При удалении выберите Удалить объект метаданных… и изучите входящие ссылки. Несохранённый исходник, устаревший план или запрет поддержки могут остановить запись. Аналоги в терминале — eska metadata copy и eska metadata delete. Параметр --dry-run позволяет сначала увидеть план. Обновление базы запускается отдельным действием.

Привязать поле формы и открыть обработчик

  1. Откройте управляемую форму в ветке Формы. Нажмите поле на изображении формы, чтобы выделить его в структуре и увидеть свойства. Команда Перейти к XML помогает сопоставить элемент с исходником.
  2. Чтобы разместить поле, перетащите реквизит из Данных в нужную группу Структуры. Редактор создаст элемент с привязкой к реквизиту. Для обычной группы используйте Добавить внутрь. Элементы можно переставлять стрелками и перетаскивать между группами.
  3. Выберите поле и измените заголовок в Свойствах. Для правила видимости или оформления по значению откройте Форма → Условное оформление…, выберите форму или динамический список и задайте условие.
  4. У нужного события нажмите Открыть или создать обработчик. Если процедуры ещё нет, редактор создаст её с параметрами события, запишет привязку и откроет код. Повторный переход ведёт в существующую процедуру.

Корректные правки автоматически записываются в исходники. Ctrl+Z отменяет правку, Ctrl+Y повторяет её, в том числе если предпросмотр открыт в отдельном окне. Если XML изменился извне или содержит несохранённые правки, разрешите конфликт и повторите сохранение черновика через Ctrl+S. Предпросмотр Designer XML 8.3.27 имеет статус beta. Проверяйте исполнение команд и BSL формы в клиенте 1С.

Для редактирования нужен Metadata API 1.53, для создания обработчиков — 1.54. В терминале eska metadata form-schema --form 'document:Заказ/form:Основная' --format json возвращает снимок и разрешённые операции. Подготовьте JSON с этим снимком, затем проверьте план через eska metadata form-edit --input form-edit.json --dry-run --format json. План применяет form-edit --plan. Навигация к процедуре и визуальное размещение доступны в редакторе. Скринкаст о правке формы.

Отредактировать запрос из BSL или XML

Откройте модуль, поставьте курсор внутрь цельного строкового литерала с запросом и выберите Открыть запрос отдельно. В новой вкладке вы увидите SDBL без удвоенных кавычек и маркеров продолжения строк. Выражения, собранные из нескольких строк оператором сложения, для этого действия не подходят. Запрос набора данных СКД или ручного динамического списка можно открыть из дерева владельца.

  1. В отдельной вкладке выберите Конструктор запросов. Проверьте приложение, если в каталоге таблиц нет нужного справочника.
  2. Добавьте источник, например Справочник.Пользователи, и выберите поле Наименование. Задайте выходной псевдоним Имя. Для отбора откройте условия и добавьте сравнение, а для порядка строк задайте сортировку. Условия соединения задаются отдельно от отбора результата.
  3. В пакетном запросе сначала выберите нужный оператор. Для объединений проверьте число и порядок выходных колонок во всех ветках. Конструктор также поддерживает подзапросы, временные таблицы, группировки и итоги. Если правка требует разместить исходные комментарии, используйте Назначить позиции исходных комментариев.
  4. Нажмите ОК, чтобы вернуть текст в отдельную вкладку, затем Ctrl+S, чтобы передать его в BSL или XML. Если исходный файл уже содержал несохранённые правки, изменения запроса появятся в том же буфере. Сохраните вкладку исходника, чтобы записать файл. Отмена закрывает конструктор с исходным текстом.

Вкладка и конструктор работают в редакторе. Для форматирования запроса в терминале есть eska fmt. Результат исполнения запроса и права доступа к данным проверяют в информационной базе. Скринкаст о запросах · Настройки форматирования.

Проверить модуль и отформатировать код

Откройте BSL-модуль выбранного приложения. Наведите указатель на метод, используйте Перейти к определению, Найти все ссылки или вызовите подсказку параметров при вводе вызова. Ошибки и предупреждения откройте в панели Проблемы. Переименование символа BSL вызывается штатной командой редактора. Имена объектов метаданных меняются в панели свойств.

Семантическую диагностику, переходы, подсказки и поддерживаемые быстрые исправления предоставляет отдельный bsl-analyzer. Спасибо автору и участникам проекта за языковой сервер BSL. Выпуски bsl-analyzer. Доступные диагностики и исправления зависят от установленной версии. Параметры диагностик задаются в Настроить проект. После смены приложения при необходимости вызовите Перезапустить анализатор BSL и проверить код заново.

Для форматирования вызовите Форматировать документ или Форматировать выделенный фрагмент. Выберите ESKA, если редактор предлагает несколько форматтеров. Настройки стиля читаются из [format] в eska.toml. Форматтер работает отдельно от анализатора. Чтобы проверить целый проект, выберите Проверить проект, подтвердите сохранение изменённых файлов и откройте диагностику в панели Проблемы. В терминале соответствующие проверки запускаются из корня проекта.

eska fmt --check
eska check --format json

Собрать файл, обновить базу и запустить отладку

Для получения CF, CFE, EPF или ERF установите платформу и компонент eska-build. Вызовите Собрать файл 1С…, проверьте тип артефакта, путь и сведения о замене существующего файла, затем подтвердите сборку. Результат можно показать в проводнике. В терминале eska build --dry-run выдаёт план, eska build выполняет сборку.

  1. Откройте Настроить проект → Запуск и отладка. Для профиля test выберите зарегистрированную базу через Из списка 1С… или укажите адрес. В поле пароля впишите имя переменной окружения. Проверить настройки проверяет введённые параметры до сохранения.
  2. В разделе Запуск и отладка → ESKA: запуск 1С выберите Обновить тестовую базу. Прочитайте план и проверьте адрес базы. Для поддерживаемых изменений доступно частичное обновление, при полном импорте редактор запросит отдельное подтверждение. Для рабочей области с базой и расширениями выберите Обновить приложение в тестовой базе.
  3. Для отдельного расширения используйте Установить расширение в тестовую базу или Удалить расширение из тестовой базы. При удалении проверьте имя и возможную потерю связанных данных. Обновление поддерживается для файловых и автономных тестовых баз.
  4. Выберите Запустить тестовую базу либо Запустить 1С с отладкой. Для второго действия нужен eska-debug и доступ к HTTP-серверу отладки. Если сеанс уже работает, используйте Подключиться к серверу отладки 1С и выберите предмет. Поставьте точку останова в BSL и выполните действие в клиенте. Во время остановки доступны стек, шаги, переменные и наблюдаемые выражения. Вычисление выражений и изменение значений обращаются к живому сеансу.

В терминале eska run запускает клиент профиля test. Команды eska apply, eska extension install и eska extension remove без подтверждения показывают план. Для записи требуется токен из плана в --confirm, для удаления расширения также --force. Для проверки настройки отладчика есть eska-debug check, для подключения другого DAP-клиента — eska-debug standalone. Справочник команд запуска и обновления.

Сравнить изменения и сохранить выбранные файлы

Откройте Система управления версиями → ESKA: изменения 1С. Панель работает через встроенное расширение Git. Один и тот же модуль виден по имени 1С, например Документ.Заказ.МодульОбъекта, и по файловому пути в подсказке. Для имён метаданных нужен Metadata API 1.54. Для неизвестного пути панель оставляет имя файла.

  1. Нажмите Открыть изменения. Для рабочей копии сравниваются файл и индекс, для подготовленных изменений — индекс и HEAD. Контекстное меню позволяет открыть исходник или посмотреть версию из HEAD. Чтобы выбрать две ревизии, вызовите Сравнить две версии. Для такого же сравнения в терминале передайте две ревизии, например eska diff --semantic HEAD~1 HEAD.
  2. Выделите файлы, относящиеся к задаче, и выберите Индексировать изменения. Передумали включать файл в коммит — выберите Отменить индексирование изменений. Команда Отменить изменения меняет саму рабочую копию и запрашивает подтверждение.
  3. Проверьте подготовленную группу и введите сообщение в поле нужного репозитория. Нажмите Фиксация либо Ctrl+Enter (Cmd+Enter на macOS).

В терминале eska status показывает состояние работы, eska diff --semantic помогает прочитать изменения в терминах 1С, а eska history выводит историю. Графические операции с индексом используют встроенный Git редактора. Перед применением отдельной CLI-команды eska save проверьте её параметры охвата файлов. Скринкаст о Git · Справочник CLI.

Если функция недоступна

Что видно Что проверить
В дереве нет конфигурации Откройте папку с eska.toml, разрешите доверие, вызовите Выбрать проект и подключиться. В Показать журнал подключения проверьте путь к компоненту и версию Metadata API.
После внешней правки дерево устарело Сохраните файл и выберите Обновить метаданные на нужной ветке. Для скрытого подпроекта верните видимость и включите проект.
Есть подсветка BSL, но нет переходов и диагностик Проверьте выбранное приложение и доступность bsl-analyzer-app. При конфликте с другим BSL-клиентом выберите, какое расширение оставить активным, затем перезапустите анализатор.
Свойство или форма не сохраняется Посмотрите причину в панели. Сохраните или разберите внешние правки XML, перечитайте актуальную версию. Для объекта на поддержке проверьте назначенное правило изменения.
Сборка или запуск прерывается Проверьте версию платформы и путь к ней, затем параметры тестовой базы. Команда eska doctor проверяет окружение проекта.
