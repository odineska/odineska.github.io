# odineska.github.io

Статический GitHub Pages сайт Odineska — открытых инструментов для разработки на 1С:

- `/` — ESKA, самостоятельные компоненты и Explorer со скриншотами;
- `/eska/` — выбор между опубликованным пакетом и текущей сборкой;
- `/eska/docs/` — подробное руководство: полная `eska` и мини-программы,
  таблица существующих команд и различий, установка, Designer XML, свойства,
  BSL, workspace/приложения, активность подпроектов, БСП, запросы и конструктор,
  форматирование, CI, Git, сборка, обновление и диагностика;
- `/eska/docs/cli/` — все 88 публичных CLI-входов с полной справкой;
- `/eska/docs/formatting/` — полный каталог параметров форматирования;
- `/eska/install` и `/eska/install.ps1` — существующие короткие адреса установщиков.

Текст руководства соответствует [`eska/docs/user-guide.md`](https://github.com/odineska/eska/blob/main/docs/user-guide.md).
При обновлении сверяйте его с CLI, `package.json` Explorer и фактическими Assets
GitHub Releases. Версия checkout и latest опубликованного пакета могут различаться.
Скриншоты хранятся в `assets/screenshots/`; на страницах можно открыть оригиналы.

Оформление «Призма»: индиго, бирюза и объёмный знак Odineska. Общие стили,
навигация и переключатель темы используются на всех страницах. При первом
открытии применяется тёмная тема; выбранная пользователем тема сохраняется.
Без доступа к localStorage переключатель продолжает работать в текущей вкладке.
Адреса GitHub-организации, репозиториев и установщиков остаются прежними.

Оптимизированные изображения знака находятся в `assets/brand/`. Montserrat
подключён локально из `assets/fonts/`; исходная лицензия SIL OFL 1.1 находится
рядом. Загрузка шрифтов со сторонних сервисов не требуется.

Шапка закреплена при прокрутке и использует полупрозрачный фон с размытием.
Переходы по якорям учитывают её высоту. В руководстве текущий раздел выделяется
в оглавлении при прокрутке, переходах по ссылкам и открытии прямого якоря.
На узком экране оглавление закрепляется под шапкой и прокручивается по горизонтали
так, чтобы текущий пункт оставался видимым.

Раздел `#practice` подробно проводит через обработку аудита активных пользователей
БСП: исходный EPF, подключение библиотеки, Git-задача, запрос, форматирование,
проверка, сборка с manifest и roundtrip. Проверена настоящая платформа в Linux ARM64;
выполнение запроса на данных рабочей ИБ описано как отдельная ручная приёмка.

Раздел `#scenarios` содержит ещё девять маршрутов: минимальный Explorer, полный цикл
разработки, EPF/ERF, проверка в CI, сборочный агент, workspace, полки, import
и patch. Команды общей `eska` и мини-программ показаны как альтернативы;
отсутствующие входы общего CLI явно отмечены. Не добавляйте примеры команд,
которых ещё нет в текущем `--help` и исходниках.

Локальный просмотр из корня репозитория, без сборки и сторонних зависимостей:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте [главную страницу](http://127.0.0.1:8000/),
[установку](http://127.0.0.1:8000/eska/),
[руководство](http://127.0.0.1:8000/eska/docs/),
[CLI](http://127.0.0.1:8000/eska/docs/cli/)
и [форматирование](http://127.0.0.1:8000/eska/docs/formatting/).

Установщики используют опубликованный канал:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://odineska.github.io/eska/install | sh
```

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://odineska.github.io/eska/install.ps1 | iex"
```

Публикация сайта выполняется существующим GitHub Pages процессом.
Локальные изменения сами по себе не обновляют публичные страницы.

Исходники подробных страниц — `docs/user-guide.md`, `docs/cli-reference.md` и
`docs/formatting.md` репозитория ESKA. На сайте сохраняются стабильные section IDs,
а ссылки на справочники ведут на локальные страницы. При синхронизации проверяйте
оглавление, вложенные anchors, таблицы, TOML/JSON-примеры, код внутри details,
desktop/mobile overflow и сохранение текста code blocks после HTML-рендеринга.
